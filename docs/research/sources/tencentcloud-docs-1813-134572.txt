什么是 Memory Hub
在多人协作使用 AI Agent 的场景中，团队常常面临三大痛点：
资产分散，难以维护： 每个成员的 Agent 提示词（Prompt）和绑定的各类资产散落在个人手中，缺乏统一的维护和更新机制。
知识孤岛，无法复用： 团队沉淀的技术文档、代码仓库以及优秀的实战经验技能，无法在成员之间无缝流转和复用。
凭证混乱，安全失控： 团队成员的各种访问凭证（如 API Key）缺乏集中的管理入口，存在安全和成本失控的风险。
Memory Hub 是云数据库 Agent Memory（TencentDB Agent Memory）专为团队协作场景打造的资产运营与协作平台。产品采用 本地管控 + 云端算力 的混合架构，从而兼顾数据安全与计算性能：
Memory Hub（用户本地 · 运营控制中心）：部署在用户本地环境，集中收拢 Prompt 与文档，将个人经验转化为标准化的团队集体资产；同时作为安全网关，对敏感数据、API Key 等访问凭证进行本地集中管控，确保敏感数据不出本地网络。
Memory 实例（腾讯云端 · 存储算力中心）：专注于提供海量向量数据的高性能存储与极速检索，并托管内置大模型的算力推理，使用户无需在本地维护昂贵的硬件基础设施。
说明：
一个 Memory 实例只能被一个 Memory Hub 面板配置，而一个 Memory Hub 面板可以配置多个实例。
核心能力
Memory Hub 将复杂的协作维度进行解耦，通过统一的可视化界面，为团队提供团队、凭证、编排、知识四大核心能力：
能力
说明
团队管理
新建与切换团队，管理团队成员，为成员分发访问凭证（user key）
Agent 编排
新建 Agent，编辑 Agent 的提示词（prompt）与绑定的知识资产
Key 管理
提供集中新建与管理成员访问凭证（User Key）的入口，确保安全合规。
知识资产：Wiki 管理
上传、查看技术文档等文本知识，并分配给指定 Agent 使用
知识资产：Code 管理
接入代码仓库，检索代码，并将代码知识分配给 Agent
知识资产：Skill 管理
创建、查看技能（Skill），支持 fork 复用他人已有技能
知识资产：Chat Memory 管理
上传、查看对话记忆，并分配给指定 Agent 使用
角色与权限
Memory Hub 区分 Admin 与 Member 两种角色，二者的职责边界如下。
角色
职责
典型操作
Admin
团队的创建者与管理者，负责团队和成员的生命周期管理
使用 Memory 实例 API Key 登录、新建/切换团队、新建成员并分发 user key、只读查看 Agent
Member
团队成员，负责自己 Agent 与资产的日常运营
使用 user key 登录、邀请成员、管理 Agent、管理知识资产、管理 Key
部署形态
Memory Hub 以 Docker 容器的形式由用户自部署在本地环境。单个容器内同时运行两个服务：
Panel（团队记忆面板） ：Memory Hub 的控制台页面，提供 Web 管理界面，承载团队、成员、Agent 与资产的管理操作。用户登录后所看到并操作的即为该页面。
Knowledge Service（知识服务，简称 KS） ：负责知识资产（Wiki、Code、Skill、Chat Memory）的存储、处理与检索。
容器启动后，通过挂载的实例配置文件连接云上已购买的 Memory 实例，拉取鉴权信息与数据，实现本地平台与云端 Memory 实例的联动。
