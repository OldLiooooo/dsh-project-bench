## 0. 审计口径与总体判断

**判定标准（五项齐备才算「已定义」）**：① 触发点明确；② 执行者明确（人/agent/系统）；③ 内容或格式明确；④ 预算/上限明确；⑤ 失败或缺失时的降级明确。两份文档在「存什么、怎么保证正确」上很扎实，在「什么时刻由谁读/写多少」上大面积缺位。

| 使用时刻 | 现有原文（只算沾边） | 缺哪几项（①~⑤） | 结论 |
|---|---|---|---|
| 会话冷启动 / teammate 开局 | WB-L1034, L1080-1081, L1979, L2028 | ②③④⑤ | ❌ 只有意图，无执行机制 |
| 干活中途写入 | WB-L2004-2022, L2039；MEM-L286, L329-330 | ①②④⑤ | ⚠️ 有工具签名与批量原则，触发点/频率未定 |
| 上下文压缩前后 | WB-L553, L1188；MEM-L140 | ①②③④⑤ | ❌ 无 flush/恢复协议 |
| 会话结束 / 交接 | WB-L301, L401, L629, L2039 | ①③④⑤ | ⚠️ 作者、格式、验证三处冲突（C12/U09-U10） |
| 隔天 / 新会话回来 | WB-L1080-1081, L1159-1160 | ②③④⑤ | ⚠️ 无「上次做到哪」摘要与续接语义 |
| 换机 / 跨 profile | WB-L879-880, L956-957, L1674 | ③④⑤ | ⚠️ 事件/事实是否随导出物走未定义 |
| 多会话 / teammate 并行 | WB-L112, L184, L195, L1548；MEM-L296, L632-636 | ①②⑤ | ❌ 可见性矩阵与记忆级写冲突规则缺失 |
| 人纠正记忆 | MEM-L502, L504；WB-L2136 | ①②③⑤ | ❌ 无入口、无传播、无回执 |
| 记忆不可用 / 损坏 / 迁移 | WB-L956, L1111, L1826；MEM-L681, L696 | ①②④⑤ | ⚠️ 未形成运行时降级体系 |

**一句话总体判断**：两份文档把记忆设计成了「**账本 + 协议 + 视图**」，但没有设计成「**一次会话生命周期内的行为**」；第 12.7 章的读写协议更像 API 说明，不像使用说明。

## 5. 一句话建议：新文档《工作台使用时的记忆》补什么、不重复什么

**只写「使用期增量」：把记忆从账本变成会话生命周期内的行为约定。**

**应该补的三块：**

1. **「记忆使用时刻」状态机**（核心）：冷启动 / 任务开始 / 回合结束 / compaction 前 / compaction 后 / 会话结束 / 隔天恢复，7 个时刻 × 6 列（触发、执行者、注入或写入内容、预算、失败降级、审计事件），一张表就能落地；所有争议先在这张表里对号入座。
2. **读写两个唯一入口的契约**：统一的记忆读/写入口（建议命名 project_brief / project_remember，或沿用 memory_recall / memory_propose，二选一并写进工具清单，见 C18）——写清 token 预算公式、角色可见矩阵、幂等与去重、verified 授权、陈旧标记与 revision 漂移检测；并补齐写入率三率（调用率 / 入库率 / 覆盖工作项率）与止损线，回应 MEM-L84 的 2475→0 证据。
3. **会话边界与恢复协议**：compaction flush/重注入清单、两类交接工件（执行者工作项交接 + PM 会话摘要）、收尾对账的 MEMORY_BEHIND 判据、跨机 export bundle 与恢复演练、权威库损坏/迁移中的分级降级。

**不该重复的**：四层/七类记忆的定义与全量 SQLite schema（记忆文档 §3、§9 已有，只引用并指定 canonical 版本）；propose→commit 六步、双时态、冲突四级流水线（已有且稳定）；人读视图清单与 lumio/开源调研（已有）；两文档之间已经矛盾的部分（如 §12.4 旧 schema）不搬进新文档，只留一行「以 MEM §9.2 为准」。
